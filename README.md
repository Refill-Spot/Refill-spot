# Refill Spot

**주변 무한리필 음식점을 찾고, 방문할 곳을 저장하고, 경험을 나누세요.**

Refill Spot은 위치와 음식 카테고리로 무한리필 음식점을 탐색하는 웹 서비스입니다.
지도와 목록에서 매장 정보를 확인하고, 마음에 드는 곳을 저장하거나 방문 경험을 사진과 함께 남길 수 있습니다.

[Refill Spot 이용하기](https://refill-spot.vercel.app)

## 주요 기능

- **지도와 목록으로 탐색:** 주변에 등록된 무한리필 음식점을 한눈에 확인합니다.
- **장소·주소 검색:** 현재 위치를 이용하거나 원하는 지역을 직접 검색합니다.
- **조건별 검색:** 음식 카테고리와 검색 반경으로 방문할 곳을 좁힙니다.
- **매장 상세 정보:** 등록된 주소·메뉴·영업시간을 확인하고 외부 지도에서 길찾기를 엽니다.
- **플랫폼별 확인:** 검증된 장소 ID가 있는 매장은 네이버·카카오 상세 페이지를 새 탭으로 바로 엽니다. 미연결 매장은 지역과 매장명으로 검색하며, 검색 결과의 지점과 주소를 확인해주세요.
- **즐겨찾기:** 관심 있는 음식점을 저장해 다시 찾아봅니다.
- **사진 리뷰:** 방문 경험을 작성하고, 내 리뷰를 수정하거나 삭제합니다.

## 이용 방법

1. **위치를 정하세요.** 현재 위치를 허용하거나 장소·주소를 검색해 선택합니다.
2. **조건을 골라보세요.** 음식 카테고리와 검색 반경을 적용합니다.
3. **매장을 확인하세요.** 지도나 목록에서 음식점을 선택해 상세 정보를 살펴봅니다.
4. **저장하고 공유하세요.** 로그인 후 즐겨찾기를 이용하고 방문 경험을 남깁니다.

음식점 탐색은 로그인 없이 이용할 수 있습니다. 즐겨찾기·리뷰 등 개인화 기능에는 로그인이 필요하며,
Google·Kakao 소셜 로그인 경로를 제공합니다. 위치 권한을 허용하지 않아도 장소 검색으로 이용할 수 있습니다.

## 이용 안내

- 등록된 음식점만 제공하며, 모든 지역의 매장이나 정보의 최신성을 보장하지 않습니다. 영업시간·가격·메뉴는 방문 전에 매장에 확인하세요.
- Refill Spot 자체 리뷰와 외부 플랫폼의 평점은 별개입니다. **네이버·카카오 평점의 자동 수집·비교·필터·정렬은 현재 제공하지 않습니다.**
- 상세 링크는 사전 일괄 매칭으로 연결합니다. 상호·지점·지역과 전화번호 또는 가까운 좌표가 함께 일치하는 단일 후보만 저장하며, 미등록·후보 충돌·조회 실패는 상세 링크를 추측하지 않습니다.
- 데스크톱과 모바일 웹에서 이용할 수 있으며, 지원 브라우저에서는 PWA로 설치할 수 있습니다. 별도 네이티브 앱이나 개인화 데이터의 오프라인 이용을 뜻하지 않습니다.

## 외부 장소 일괄 연결

사용자가 리뷰 버튼을 누를 때 외부 API를 호출하지 않습니다. 아래 명령으로 미리 조회·매칭하고 ID를 저장한 뒤에는 상세 페이지를 한 번에 엽니다.

1. `202610240001_store_place_ids.sql`, `202610250001_invalidate_changed_store_places.sql`을 순서대로 적용합니다. 두 번째 마이그레이션은 상호·주소·전화·좌표가 바뀐 가게의 기존 연결을 자동으로 해제합니다.
2. `.env`에 Supabase URL/키와 `KAKAO_API_KEY`를 설정합니다. 쓰기에는 서버 전용 `SUPABASE_SERVICE_ROLE_KEY`가 필요합니다. 네이버 장소 ID는 일반 지역 검색 API가 제공하는 업체 홈페이지와 다르므로, 설치된 Aside CLI와 설정된 브라우저로 공개 검색 화면의 실제 장소 링크를 읽습니다. 차단이나 로딩 실패를 우회하지 않고 오류로 기록합니다.
3. `pnpm places:sync`로 전체 가게를 조회합니다. 기본은 **DB를 변경하지 않는 dry-run**입니다. `--platform kakao` 또는 `--platform naver`, `--ids 1851,1852`, `--limit 10`으로 범위를 좁힐 수 있습니다.
4. `logs/place-links.json`에서 처리 상태와 장소 ID/URL을 확인합니다. 외부 응답의 상호·주소·전화·좌표는 보고서에 보관하지 않습니다. `--resume`은 동일한 가게 정보와 24시간 이내 요약으로 dry-run 중복 조회를 줄이며, 오류는 다시 시도합니다. 이전 v1 전체 응답 보고서는 재사용하지 않습니다. 네이버는 한 가게씩 순차 조회하고, 플랫폼별 오류가 3회 연속 발생하면 미처리 건수를 남기고 중단합니다.
5. `pnpm places:sync --resume --apply`는 새로 저장할 링크를 실시간 재조회·재매칭한 뒤 ID만 저장합니다. 저장된 요약은 신원 검증 근거로 재사용하지 않습니다. 조회 이후 가게 정보나 기존 ID가 바뀌면 덮어쓰지 않고 충돌로 기록합니다.

신규 가게 등록 후 또는 정기 운영 작업으로 같은 명령을 실행합니다. 스케줄러 등록은 이 명령이 수행하지 않습니다. ID가 없는 가게는 검색 버튼을 유지하며, 애매한 후보만 별도 검토하면 됩니다. 오류/충돌이 있으면 종료 코드 2와 체크포인트를 남깁니다. 공개 검색 화면 구조가 변경되면 네이버 수집기를 점검해야 합니다.

## 원본 데이터 점검과 최신화

`node --import tsx scripts/audit-store-data.ts`는 DB를 읽기만 하며 품질 지표와 기존 DB 입력 스냅샷을 `logs/store-data-audit*.json`에 남깁니다. `node --import tsx scripts/pilot-store-refresh.ts`는 대표 사례만 조회하고 외부 장소 ID/URL과 조회 상태만 기록합니다. 두 명령 모두 매장 정보를 수정하지 않습니다.

현재 전체 최신화는 출처 확인 단계입니다. `created_at`/`updated_at`과 `browser_verified` 메뉴 표시는 실제 확인일이나 출처를 증명하지 않습니다. 지도 검색의 성공은 영업·가격·무한리필 운영 여부의 검증이 아니며, 검색 누락은 폐업 판정이 아닙니다.

[카카오 공식 FAQ](https://devtalk.kakao.com/t/faq-api/125610)는 로컬 API 응답의 별도 저장·사용을 제한하며, [담당자 안내](https://devtalk.kakao.com/t/api-id/152228)는 상세 연결용 장소 ID/URL 저장을 허용합니다. 따라서 API 응답의 주소·좌표 등을 원본 매장 DB 최신화에 복사하는 방식은 사용하지 않습니다. 기본 정보는 저장·재사용이 허용된 출처, 가격·영업시간·무한리필 여부는 매장/사업자 확인 등 항목별 근거가 확보된 뒤 갱신해야 합니다. 공개 페이지가 보인다는 사실만으로 재사용 권한이 생기지 않습니다.

## 크롤러 데이터 검토

현재 신규 매장 수집·등록 범위는 서울 25개 자치구입니다. 검색 결과에 나타난 원본 ID는 신규 후보일 뿐이며, 서울 주소·동일 지점·무한리필 근거·중복 여부 확인 전에는 공개하지 않습니다. 기존 정보와 좌표도 검토 없이 덮어쓰지 않습니다.

`/contact`의 기존 가게 등록 접수에서 신규 가게 제보와 기존 정보 수정 제보를 받습니다. 서울 주소, 리필 범위와 설명을 입력하고 선택적으로 근거 링크·확인일을 제공할 수 있습니다. 접수 내용은 관리자 검토를 기다리는 `pending` 문의로만 저장하며 자동으로 매장을 생성하거나 수정하지 않습니다. 수집 데이터와 사용자·사업자 제보의 출처를 혼동해 안내하지 않습니다.

별도 `refill-spot-crawler`의 staging v1 JSON을 `node --import tsx scripts/check-crawler-staging.ts <파일경로>`로 검사합니다. 원본 장소 ID·출처·관찰시각·근거·조건을 보존하며 일반 메뉴를 무한리필 상품으로 승격하지 않습니다. `main_meal`/`buffet`과 `side_refill`을 구분합니다.

크롤러의 `confirmed`는 출처에 명시된 상품을 추출했다는 의미이지 현재 판매를 보증하지 않습니다. `currentness: unverified` 입력은 모두 `needs_review`로 남고 운영 DB나 공개 화면에 자동 반영되지 않습니다. 라이브 수집은 출처 이용 조건과 접근 정책을 확인한 뒤 수행해야 합니다. 기존 439곳은 이 검사만으로 최신화되지 않습니다.
